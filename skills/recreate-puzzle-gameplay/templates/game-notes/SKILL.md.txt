Project-specific companion to the general puzzle recreation skills
(`puzzle-evidence-extraction`, `puzzle-gameplay-build`, `puzzle-gameplay-verification`).
It records where this game's evidence and code live and what was learned. It is not
permission to implement unrequested mechanics: investigation produces findings,
implementation produces the requested change and its checks.

## Start with the current project

1. Read [the source map](#source-map) below, then `<workdir>/progress.json`,
   `<workdir>/decisions.md` and `<project>/ProjectSettings/ProjectVersion.txt`.
2. Read only the evidence and code for the requested mechanic. The historical baseline is
   <N> base levels on Unity <version>, final run `checks/<run-id>/` on <date>; inspect the
   current files before relying on it.
3. Load the general skills for the phase you are in. Editor control: `unity-pipeline` or
   `unity-cli`. New decompile work: `unity-apk-decompile`.
4. Keep unrelated edits, Unity GUIDs and `.meta` files. Never commit, stash or reset.
   Never save, discard or replace a user scene.

## Establish the behavior contract

Before changing behavior, write the claim rows (template in `puzzle-evidence-extraction`)
for the requested mechanic and label each:

| Label | Meaning |
|---|---|
| Proven | Original bytes, schema, native branch, prefab or reference frame proves this exact claim |
| Observed | A reference frame/video or a current Unity interaction shows it; say which |
| Inferred | A reconstruction choice that explains the evidence; not recovered behavior |
| Unknown | Missing, contradictory or insufficient evidence |

Match the source to the question: level membership and fields from the original catalog
and decoded JSON with hashes; eligibility, capacity, order and reset from native branches
plus schema; appearance from references and the active prefab, mesh GUIDs and materials;
interaction from real pointer events. An `Inferred` choice gets a `decisions.md` line when
you make it.

## Verify rules, interaction and appearance separately

1. Model contracts from claim rows, including reject and boundary rows. Expected values
   come from the source column, not from the code under test.
2. Compile outside Play Mode and read the result; a submitted request is not a compile.
3. Real Input System pointer events for the changed path; a direct method call is setup.
   Wait for the receipt, read `report.txt`, judge with `check_evidence.py --strict`.
4. Screenshots portrait and landscape for every affected level, beside the reference.
5. Only the last run on the final code and assets counts; an older PASS is history.
